# GEO 文章要素检查 Skill（通用版）

本 Skill 用于检查和修正规范面向 AI 引擎（Generative Search/AIO、RAG、ChatGPT、Perplexity、Google AI Overviews、Grok 等）检索与引用的页面内容。核心原则：**一页 = 一组可被单独引用的答案资产（Answer Asset），每个 H2 是一个独立答案，答案必须前置**。

## 1. 何时使用

在以下任意场景时，**必须**使用本 Skill 校验：

- **新建页面/新文章**（生成 HTML 页面）
- **大幅改写**现有文章内容
- **重构章节结构**（新增/合并/调整 H2）
- **补充数据、案例或来源**
- **发布前内容质量把关**
- **内容审计（Content Audit）**

## 2. 核心 GEO 原则

1. **一页一主题（Single Intent）**：整页只聚焦一个用户查询。
2. **答案前置（Answer-First）**：每个 `H2` 下首 1～2 句直接给出答案，再展开论证。
3. **按区块可引用（Chunkable）**：每个 `H2` 都应能独立成为可被 AI 摘录的答案片段。
4. **结构化优先（Structured）**：列表、表格、`<blockquote>`、FAQ 等更易被 AI 解析与引用。
5. **可验证性（Verifiability）**：关键结论、数据、研究需有清晰来源或出处。
6. **问题驱动（Question-Led）**：优先用问题式标题（H2）贴合自然语言搜索。

## 3. 快速自动校验

如项目中有现成的校验脚本，可按需使用。通用项目也可按下方清单人工优先完成。

推荐自动化检查项（结构性）：
- H1 是否存在且唯一
- H2/H3 层级是否合理
- 是否存在 `Article/FAQPage/BreadcrumbList` JSON-LD（如使用结构化数据）
- `canonical`、`datePublished`、`dateModified` 是否存在
- 段落是否存在极长段落（>6 行）等结构问题

> **注意**：自动化只能检查「有无」，无法判断「答案是否前置」「开场是否场景化」「来源是否充分」。**必须配合第 4 节人工清单**。

## 4. 人工检查清单（必查项）

### 4.1 标题与结构
- [ ] **H1 聚焦**：简短有力（≤110 字符），直接对应核心查询意图。
- [ ] **一页一主题**：页面未混入不相关主题。
- [ ] **H2 问题式**：大部分 H2 以 What/How/Why/Which/When/Do/Can/Should 开头（优先自然语言提问）。
- [ ] **每个 H2 可独立成答**：每个小标题都能回答一个清晰的问题。
- [ ] **层级清晰**：只在必要时使用 H3，避免深层嵌套。

### 4.2 答案前置与开场
- [ ] **场景化开场**：首段自然带入用户困惑/场景，而不是「This article will introduce...」。
- [ ] **答案前置（强制）**：**每个 H2** 下首 1～2 句必须直接给出答案（结论），再展开论证、案例、细节。
- [ ] **关键定义突出**：核心定义、判断标准用 `<blockquote><strong>...</strong></blockquote>` 强调（最易被 AI 引用）。
- [ ] **术语全称**：首次出现专业术语时附全称，如 `Generative Engine Optimization (GEO)`。

### 4.3 内容质量
- [ ] **段落精短**：每段 ≤ 6 行（≤ ~440 字符）。长句拆短，避免大段纯散文。
- [ ] **结构化呈现**：对比、维度、数据优先用 `<table>`；操作步骤用 `<ul>/<ol>`；要点清单用列表。
- [ ] **可验证来源**：数据、研究、行业结论**必须**标注来源（名称/年份/链接至少其一）。
- [ ] **具体案例**：建议/结论优先结合具体场景或案例，而非空泛表述。
- [ ] **结尾总结**：页面末尾 1～2 句总结核心结论（如 `In short: ...`）。

### 4.4 SEO/GEO 元数据与结构化
- [ ] **canonical**：指向最终落地 URL（一致且唯一）。
- [ ] **日期正确**：`datePublished` 保持**首次创建日**不变；`dateModified` 更新为**本次修改日**（YYYY-MM-DD）。
- [ ] **Article JSON-LD**：含 `headline`、`author`、`publisher`、`datePublished`、`dateModified`、`mainEntityOfPage`、`inLanguage: "en"`。
- [ ] **FAQPage JSON-LD（按需）**：问答类页面建议添加，问题需与页面实际内容一致。
- [ ] **BreadcrumbList JSON-LD（按需）**：有面包屑时同步。
- [ ] **RSS/canonical 一致**：站点若有 feed/alternate 链接，保持路径一致。

### 4.5 可用性与规范
- [ ] **图片可访问**：`<img>` 含描述性 `alt`，`max-width: 100%`。
- [ ] **导航完整**：章节内保留上下篇导航（`Previous/Next`）为佳。
- [ ] **统计脚本（如存在）**：**绝不删除或修改**现有统计/分析脚本。
- [ ] **保持站点约定**：遵循项目现有 HTML/CSS 规范（内联样式、编码、标签顺序等）。

## 5. GEO 反模式（命中即 FAIL）

| 反模式 | 修复建议 |
|---|---|
| **纯散文，无小标题** | 按用户疑问拆分成 H2（问题式）。 |
| **答案埋在段落中间** | 将结论提至 H2 下首 1～2 句，先答后述。 |
| **「This article introduces...」式开场** | 改用场景/困惑/提问自然带入。 |
| **观点无来源** | 补充出处（报告/机构/年份或可验证链接）。 |
| **一页多主题** | 拆分成独立页面，每页聚焦单一查询意图。 |
| **段落 > 6 行** | 拆成更短段落，必要时用列表/表格替代。 |
| **堆砌缩写未全称** | 首次出现补全称（缩写在括号内）。 |
| **数据纯文本堆砌** | 用 `<table>` 呈现对比/数值类信息。 |
| **标题纯名词无疑问** | 改为问题式 H2，贴合自然语言提问。 |

## 6. 校验流程（推荐顺序）

1. **定大纲**：列出 `H1 + 全部 H2`（问题式），确认**一页一主题**。
2. **逐节写作**：每个 H2 → **首句答案前置** → 短段落/列表/表格/blockquote 展开。
3. **要素补全**：术语全称、来源、定义块、结尾总结。
4. **结构化校验**：JSON-LD、canonical、日期（`datePublished` 不变，`dateModified` 更新）。
5. **索引同步**：按项目约定同步 sitemap/导航/feed/summary 等相关索引文件。
6. **全量复核**：先过第 3 节快速检查，再逐项完成第 4 节清单，确保 0 项反模式（第 5 节）。
7. **最终确认**：复核一次「每个 H2 首句是否直接回答该 H2 的问题」。

## 7. 最低通过标准（Hard Gate）

新页面**必须**满足以下最低要求方可发布：

- [ ] H1 聚焦 + 全部 H2 问题式 + **一页一主题**
- [ ] **每个 H2 首句答案前置**
- [ ] 大部分段落 ≤ 6 行
- [ ] 核心定义使用 `<blockquote><strong>...</strong>`
- [ ] 对比/数据类信息使用表格（如有相关场景）
- [ ] 首次术语附全称，关键结论有来源标注
- [ ] 页面末尾有 1～2 句结论总结
- [ ] 必要的 JSON-LD（Article，问答类加 FAQPage）字段基本完整
- [ ] canonical、日期字段正确（`dateModified` 已更新，`datePublished` 未变更）
- [ ] 相关索引文件已按需同步
- [ ] 未触发第 5 节任何反模式

## 8. 使用说明

使用本 Skill 时，请**按清单逐项检查**，不满足项必须修复后再通过。优先保证「答案前置 + 一页一主题 + 可验证来源」这三个核心要素。
